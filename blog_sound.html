Sound

Sound is processed in fixed chunks. The size of these chunks determines the latency of the audio. Say you're processing sound in 50 ms chunks. 30 ms has passed since the last buffer swap, and you start playing a sound. It can mix 20 mx into the "back buffer", but that won't be submitted for another 30ms. The size of these chunks or buffers is up to you. If the buffers are too small, the audio crackles. If the buffers are too large, there is noticable latency. So what is the right size? I'm not sure. Anecdotally, i've read that the latency becomes noticable at around 50 ms.

Sound API's fall into what i call "push" and "pull" api's. A "Push" API expects you to submit data in fixed intervals, it's up to you to call the function that pushes data. A "Pull" API will usually take a function pointer, and call it at fixed intervals. Direct Sound has a "Push" API, FMOD has a "Pull" API. For this blog, we're going to assume you're working with a "Push" type of API, and are writing to one big circular buffer.
