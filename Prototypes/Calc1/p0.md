# Calcul8or game

Implement using phaserjs. Can load phaserjs from CDN.
Other than that, include no external libraries or assets.

We're going to build a calculator puzzle game. In this game the player will be presented with a number, and a set number of buttons that modify the number. The player must use the provided operations to reach the goal number in a set amount of turns.

Implement the game in a single html file (index.html). The game config might be something like:

```
 document.addEventListener('DOMContentLoaded', function() {
    const config = {
        type: Phaser.AUTO,
        parent: 'game-container',
        scale: {
            mode: Phaser.Scale.FIT,
            autoCenter: Phaser.Scale.CENTER_BOTH,
            width: 720,
            height: 1280
        },
        resolution: window.devicePixelRatio || 1,
        antialias: true,
        pixelArt: false,
        roundPixels: false,
    };

    const game = new Phaser.Game(config);
});
```

## UI

The UI of this game should look like a clean vector drawn calculator. You can achieve this look by:
* The top 1/2.5 of the screen is the calculator screen. To draw the calculator:
    * Draw a dark box with rounded corners.
    * In the upper left, have the level number in a lighter text, ie: Level: 7. This text should use a 50px font size.
    * In the upper right have something that looks like a solar charger for the calculator
    * Below that have a light green ish square with rounded borders that fills out the rest of the box, this is the screen
    * The screen's top has three icons (85px tall each). The first one is just a smily face (120 px wide). The second one (250px wide) is a dark square with light text "moves: x", and the third one (210px wide) is also a dark square with light text "goal: x". The font size on these can be 40.
    * Below that is the current value. This is just a text field that will display a single line of text (usually a number). It should be right aligned and be 120px.
    * And below that is a smaller line of text for hints if requested
* The bottom of the screen is a three by three grid of buttons. Make them rounded, but give them a raised drop shadow look.
* We need to support the following types of buttons:
    * EMP: Empty (slightly darker than background, should look disabled)
    * CLR: The clear button (red)
    * RST: The level reset button (red)
    * NXT: The next level button (green)
    * HNT: The hint button (blue)
    * OPT: The options button (yellow)
    * LVL: Level sellect button( dark gray, just a number)
    * +num: Addition (dark gray)
    * -num: Subtraction (dark gray)
    * xnum: multiplication (dark gray)
    * /num: division (dark gray)


## UI Notes:

* All elements of the display should be in a single container.
* All buttons should be in a single container
* The number display should be right aligned.

The smily face changes based on how the player is doing.:
    * It's normally a usual smily face.
    * On win, it does an open mouth smile.
    * On lose it becomes a frowny face.
    * It should be drawn with vectorw, not emojis
    * The emoji is a robot, so it's face is rectangular not round. At least 3x as wide as it is tall.
    * Draw it using a rounded rectangle

In terms of overall color, the game should be a medium dark theme, and the background color should be a little darker than the game background.

When laying out the game buttons:
    * Figre out the available width and height
    * Keep room for some margin, but lay the buttons out so they remain square and fill all possible available space
    * Have it be centered in the available bottom area to ensure all buttons will be visible. Avoid aligning it to the bottom without a margin.
    * The buttons should not move in x or y on mouse over, as that would invalidate their interactive position. Instead they should scale up on hover.
    * Since the button graphics scale, they need to have an origin of 0.5 so they scale around their local center.

## Gameplay

* The payer is presented with the information for the current level. 
* Player presses one or more of the buttons.
* Each button updates the value on the display screen.
* If the player hits the hint button, the hint is also displayed.
* The clear button resets the number to its initial value.
* If the player gets the number in the right set of moves, the display changes from numbers to "WIN", all buttons become empty, except the clear button, which changes into a next button. When the next button is clicked, the next level is loaded. Levels cycle around.
* If the player runs out of moves the display changes from numbers to "LOSE", all buttons become empty. The clear button turns into a reset (RST) button.

If the user clicks the options button, change 8 of the buttons to LVL buttons (but the option button in the lower left remains the same). Each of these buttons will reset the game to the level that coresponds to the button number (and close the menu). Clicking option again resumes the game. The display should read "PAUSED" not a number while this menu is open.

A set number of moves is shown to the player. Clicking any button that does a math operation will subtract one from the number of moves. If the player has 0 remaining moves they loose the level.
